# HTTPS и HSTS перед публикацией

Локальный контейнер Nginx работает по HTTP только для разработки и проверки. HSTS нельзя включать на localhost и нельзя добавлять его в этот контейнер до того, как домен будет подключён к внешнему HTTPS-прокси или хостингу.

## Что настраивается на хостинге / reverse-proxy

1. Подключить реальный домен и выпустить действующий TLS-сертификат.
2. Сделать постоянный редирект с HTTP на HTTPS.
3. Передавать запросы к контейнеру сайта по внутренней сети; наружу публиковать только HTTPS.
4. После проверки всех адресов, включая /admin/, добавить заголовок:

    Strict-Transport-Security: max-age=31536000; includeSubDomains

5. Проверить сертификат на основном домене и на всех используемых поддоменах, прежде чем оставлять includeSubDomains.

Не добавляйте preload: это необратимое для пользователей решение и оно не нужно для первого релиза.

## Что уже включено в контейнере сайта

- Content-Security-Policy с разрешениями только для самого сайта и Яндекс Метрики;
- запрет встраивания страницы во фрейм;
- запрет загрузки объектов, камер, микрофона и геолокации;
- nosniff и безопасная политика Referer.

После релиза нужно повторно проверить заголовки на настоящем HTTPS-домене, отправку формы, вход в админку и загрузку Яндекс Метрики после согласия на аналитику.
